# Postmortem 模板

> 复制本文件，填写实际事故信息。无指责文化，根因归系统而非个人。

```markdown
# Postmortem: {事件简述}

**日期**：YYYY-MM-DD
**级别**：P0 / P1 / P2
**影响**：X 个用户，Y 小时
**作者**：@xxx
**参与者**：@xxx @xxx

## TL;DR

3-5 句话总结发生了什么、为什么、怎么修的。

## 时间线（按时间顺序）

- **HH:MM** 触发（用户报告 / 监控告警）
- **HH:MM** oncall 确认
- **HH:MM** 紧急 patch / 回滚
- **HH:MM** 临时缓解
- **HH:MM** 根因定位
- **HH:MM** 修复上线
- **HH:MM** 完全恢复
- **HH:MM** 复盘会

## 影响

- **用户**：X 个，集中在 {场景}
- **业务损失**：¥Z
- **持续时间**：Y 小时
- **数据丢失**：R 分钟（≤ 实际 RPO）

## 根因（5 Whys）

- 问题：是什么直接导致？
- Why 1：为什么？
- Why 2：为什么？
- Why 3：为什么？
- Why 4：为什么？
- Why 5：根本原因（系统/流程/人）

## 为什么没拦住

- 监控：为什么没告警 / 告警了为什么没及时处理
- 测试：为什么 CI 没抓到 / E2E 漏场景
- 流程：为什么没走变更评审

## 时间线图

```
HH:00 ──── HH:00 ──── HH:00 ──── HH:00 ──── HH:00
   触发     确认       临时缓解     根因        修复
```

## 改进项

| 改进 | 类型 | 优先级 | 负责人 | 截止 |
|------|------|--------|--------|------|
| 加 X 监控 | 预防 | P1 | @xxx | MM-DD |
| 加 Y 回归测试 | 检测 | P1 | @xxx | MM-DD |
| 重构 Z 代码 | 修复 | P2 | @xxx | MM-DD |
| 写 W Runbook | 知识沉淀 | P2 | @xxx | MM-DD |

## 教训（无指责）

- 这次事故教会我们...
- 系统的什么缺陷暴露了
- 下次如何更早发现、更快响应

## 沟通

- 用户公告：{链接到发版说明}
- 团队分享：{会议纪要链接}
- 客户/合作方：{邮件链接}

---

*模板版本：v1.0*
```

## 命名规范

`docs/postmortem/YYYY-MM-DD-{slug}.md`

例：
- `2026-07-15-minimax-outage-2h.md`
- `2026-08-03-pinecone-quota-exhausted.md`
- `2026-09-10-db-corruption-after-deploy.md`
